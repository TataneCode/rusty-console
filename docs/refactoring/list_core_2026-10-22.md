# ListCore<TItem> — Shared List State and Rendering — 2026-10-22

Refactoring series landing the "niveau 1" plan: factor the list behavior
duplicated by the five list screens (container, image, network, volume, stack)
into shared generic components in `04_presentation/tui/common/`.

See **ADR-002** in `ARCHITECTURE.md` for the decision record.

## What changed

### New shared components

- `common/list.rs` — `ListCore<TItem>`: owns `items`, `selection`, `filter`,
  `sort_order`, `loading`, `error` and the 13 shared methods (navigation,
  filter, sort, loading, error, `filtered_items`, `selected_item`). The filter
  predicate and sort key are injected as `fn` pointers at construction.
  15 unit tests.
- `common/list_view.rs` — `render_list()` + `ListViewSpec` (static screen
  description: title, headers, widths, help texts) + `ListRenderInput`
  (runtime: items, selection state, active filter, loading/spinner) +
  `ListHelpBar`. 3 render tests on `TestBackend`.

### Presenters migrated (composition + `Deref`/`DerefMut`)

| Presenter | Specific state kept in the presenter |
|---|---|
| `VolumePresenter` | `selected_volume` (details) |
| `ImagePresenter` | `selected_image`, `pull_progress` |
| `NetworkPresenter` | `selected_network`, `container_selection` |
| `StackPresenter` | `stack_containers`, `container_selection` |
| `ContainerPresenter` | logs, log search, runtime stats, `selected_container` |

Because of `Deref`/`DerefMut`, call sites (`presenter.selection`,
`presenter.filter`, `presenter.navigate_up()`, …) and almost all tests work
unchanged. The only test edits are field renames `p.<items>` → `p.items`
(6 assertions across presenter tests and `app.rs`).

### Views migrated

The five `render_*_list` functions are now thin wrappers: a `ListViewSpec`
literal + a row closure. The image list keeps its pull-progress bar overlay
as a specific case (redrawn over the help area while a pull runs).

### Incidental fixes (documented, no visible behavior change)

- `NetworkPresenter` gains the `error` field it previously lacked
  (uniformization via `ListCore`).
- Dead `if !loading {}` branch removed from `StackPresenter::set_loading`.

### Naming convention (same PR)

Generic parameters get meaningful names: `TItem` (list item type),
`'frame` (ratatui widgets lifetime), `'text` (borrowed display strings),
`'items` (filtered slice references). See
`docs/refactoring/generic_parameter_naming_2026-10-22.md`.
