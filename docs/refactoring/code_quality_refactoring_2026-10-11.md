## Step 0 — MIT license

- Added `LICENSE` (MIT, Copyright (c) 2026 TataneCode).
- `Cargo.toml`: `license = "MIT"` and `repository` fields.
- `README.md`: new `## License` section.

Unplanned but required: the CI Clippy job failed on `main` because the stable
toolchain (1.99) ships the `clippy::double_must_use` lint, which fires on the
`#[must_use]` generated by `async_trait`/`mockall::automock` over `Result`-returning
trait methods. Fixed with targeted `#![allow(clippy::double_must_use)]` on the four
repository trait files.

## Step 1 + 3 — Remove `allow(dead_code)`, deduplicate entry points

Key finding: `cargo check --lib` produced **0 warnings**. The 33 `dead_code` warnings
in the binary were artifacts of `main.rs` redeclaring every module with `#[path]`,
recompiling them privately. No real dead code existed; deleting anything would have
destroyed healthy code.

Fix: `src/main.rs` is now a thin `fn main()` that consumes the library crate
(`use rusty_console::...`). Module declarations live only in `src/lib.rs`. Result:
zero warnings on `--all-targets`, both `#![allow(dead_code)]` removed, no code deleted.

## Step 2 — `src/shared.rs` dissolved into its layers

`src/shared.rs` sat outside any layer, breaking the DDD layering story.

- `PruneResultDto` → `src/02_application/shared/dto.rs` (application transport type)
- `ByteSize` → `src/01_domain/shared/byte_size.rs` (pure business primitive, zero deps)
- Removed the `pub type ... = crate::shared::...` aliases in the layer `mod.rs` files
- Rewrote all 47 `crate::shared::*` references to the proper layer paths
- +1 unit test (289 total at the time)

## Step 4 — Enum variant renames

Removed both `#[allow(clippy::enum_variant_names)]` by renaming variants instead:

- `DomainError`: `InvalidContainerId` → `InvalidContainer`, `InvalidVolumeId` →
  `InvalidVolume`, `InvalidImageId` → `InvalidImage`, `InvalidStackName` → `InvalidStack`
- `ConfirmAction`: `DeleteContainer(bool)` → `ContainerDelete(bool)`, `DeleteVolume` →
  `VolumeDelete`, `DeleteImage(bool)` → `ImageDelete(bool)`, `PruneContainers` →
  `ContainersPrune`, `PruneVolumes` → `VolumesPrune`, `PruneImages` → `ImagesPrune`,
  `RemoveAllStackContainers` → `StackContainersRemoveAll`

Lesson learned: a global `sed` also renamed bollard's `PruneContainersOptions` types,
caught immediately by `cargo check` (3 errors) and reverted for those symbols.

## Step 5 — Splitting `app.rs` (2,726 → 1,798 lines)

Three incremental commits, each independently green:

1. **`exec.rs`** (225 lines): `ExecCommandConfig`, `ExecShell`, `ExecRefreshTarget`,
   `PendingExec`, `ExecCommandResult`, `ExecShellDialog`, `build_exec_command()`,
   `format_exec_error()`, `finalize_exec_command_result()` + 4 tests.
   `std::process::Command` was kept (not `tokio::process`) because the TUI is
   suspended during exec — identical behaviour, lower risk.
2. **`confirm.rs`** (93 lines): `ConfirmAction`, `confirm_message()` + 4 tests.
3. **`router.rs`** (718 lines): all screen-action handlers in a separate `impl App`
   block — dispatch over `Screen`, per-screen handlers, `execute_confirm_action`,
   filter handling, image pull, stats streaming.

`app.rs` keeps the `App` struct, its state, `run()` (event loop), rendering, and data
loading. Some members/methods became `pub(crate)` to support the external `impl App`.

## Step 6 — Tokio features narrowed

`tokio = { features = ["full"] }` → `["rt-multi-thread", "macros", "sync", "time", "process"]`,
derived from an actual usage inventory (`cargo tree` + grep):
- `rt-multi-thread` — `#[tokio::main]` runtime
- `macros` — `#[tokio::main]` / `#[tokio::test]`
- `sync` — `mpsc`/`oneshot` (stats streaming, image pull)
- `time` — timers used by bollard streams
- `process` — `tokio::process::Command` (stack adapter)

## Step 7 — MSRV declared

  all green on that toolchain
